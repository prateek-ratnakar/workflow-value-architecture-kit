# Value realization

## 1. KPI tree
Start from one financial outcome and decompose until each leaf is a metric a team controls.

```
Cash released from deductions
  = invalid deductions recovered + cycle time reduction x daily volume x value
    invalid deductions recovered = identified invalid x recovery rate
    identified invalid           = cases decided x share invalid x decision accuracy
```

## 2. Baseline before anything else
Measure the baseline on the client's own data, over a period long enough to cover seasonality. A business case built on vendor benchmarks will be challenged, and should be.

## 3. Business case structure
| Section | Content |
|---|---|
| Problem and baseline | Measured current state and leakage |
| Options | Including do-nothing and a non-AI process fix |
| Benefits | Per KPI, with owner and timing |
| Costs | Build, run, token and change costs |
| Risks and sensitivities | What has to be true; downside case |
| Decision | Go, no-go or pilot, with the gate criteria |

Always include the non-AI option. Some of the best outcomes route an idea to a policy, tooling or process fix instead of a model.

## 4. Benefits tracking
Monthly register per benefit: baseline, target, actual, variance, owner, action. Realization is reported against the original baseline, not a re-based one. Benefits are only counted when finance agrees they have landed.

## 5. Challenge the brief
A value case is also the tool for pushing back. When a mandate would destroy more value than it saves, the same baseline, options and sensitivities make the counter-proposal.
